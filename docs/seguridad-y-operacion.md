# Seguridad y operación

Estado revisado: **29 de octubre de 2026**, actualizado con el lote `codex/administracion-ciberseguridad`. Alcance: código del repositorio; no se verificó la configuración de un servidor público ni se realizó una prueba de penetración en esta entrega. Este documento sustituye como referencia vigente a las revisiones de seguridad fechadas; éstas conservan valor histórico.

## 1. Posición actual

RegioMóvil combina API ciudadana anónima, SQLite y moderación por panel privado o CLI. El panel usa Better Auth 1.7.14, TOTP obligatorio, roles y sesiones/CSRF; está deshabilitado por defecto. Existen instrumentación privada, Compose Prometheus/Grafana, copias online y CI de seguridad. El stack y las regresiones se comprueban en entornos temporales; no acreditan instalación remota, operación sostenida ni una evaluación de conformidad OWASP completada.

La exposición pública requiere un responsable de operación, HTTPS, volumen persistente, respaldo recuperable y capacidad de revisar/retirar contenido. CORS restringe navegadores; **no identifica personas ni impide solicitudes de clientes ajenos a un navegador**.

## 2. Activos, límites de confianza y amenazas

| Activo o frontera                         | Riesgo principal                                                    | Defensa actual / trabajo pendiente                                                                                                                                 |
| ----------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Dispositivo → API anónima                 | Abuso de solicitudes, spam, contenido falso                         | Validación y cuotas por socket; falta protección compartida en el ingreso y estrategia de abuso para varias réplicas.                                              |
| Foto/texto → almacenamiento → publicación | Datos personales, contenido dañino, archivos manipulados            | Privado por defecto, consentimiento, revisión humana y validación de imagen. No hay detección ni difuminado automático de rostros/placas.                          |
| API → proveedores de lugares              | Agotamiento de cuota, fuga de consultas, SSRF                       | URL configurada en servidor, restricciones de transporte y respuesta. Revisar proveedor y contrato de tratamiento antes de escalar.                                |
| Persona autorizada → panel/API privados   | Robo de acceso, lectura de fotos, publicación o cambios sin permiso | TOTP por sesión, rol en servidor, cookies protegidas, origen/CSRF, versión atómica y revocación; evaluación independiente y recuperación institucional pendientes. |
| Host → SQLite y CLI                       | Lectura de evidencia privada, alteración de moderación              | Permisos locales y transacciones. Quien controla el host/base puede cambiar registros; la bitácora no es inmutable.                                                |
| Cliente → mapa, GPS y guardados           | Exposición de localización o pérdida de borradores                  | GPS de primer plano y guardados explícitos; el almacenamiento local no es una caja fuerte frente a un dispositivo comprometido.                                    |
| Dependencias, CI y artefactos             | Introducción de código vulnerable o publicación incorrecta          | Lockfile, CI de dependencias/secretos y reglas SAST locales; faltan evaluación de imágenes/host y revisión del despliegue.                                         |

No se reciben datos de localización de unidades operadoras. Las estimaciones sintéticas y los reportes comunitarios son fuentes distintas y deben seguir siéndolo.

## 4. Evaluación OWASP parcial y cierre pendiente

Usar **ASVS 5.0.0** como catálogo de requisitos y **WSTG 4.2** como guía de pruebas, versiones estables comprobadas el 29 de octubre de 2026. El [estándar](https://asvs.owasp.org/) y la [guía versionada](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/) cumplen propósitos distintos; un escáner no proporciona una aprobación integral.

La [matriz de verificación](matriz-owasp.md) desglosa controles seleccionados, evidencia y brechas de este lote. La tabla siguiente conserva un mapa de los [capítulos versionados de ASVS](https://github.com/OWASP/ASVS/tree/v5.0.0/5.0/en), **no una evaluación ni un listado completo de requisitos**. Seguridad debe fijar nivel y alcance, registrar cada requisito aplicable con identificador/versionado, evidencia, resultado, responsable y excepción justificada. Propuesta: evaluar nivel 2 para el servicio que custodia evidencia privada y administración; aún no es un compromiso aprobado.

| Área ASVS 5.0.0                                             | Pruebas WSTG 4.2 a desarrollar                            | Entregable pendiente                                                                                                                                                                                |
| ----------------------------------------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| V1 codificación, V2 validación, V4 API, V5 archivos         | 4.7 entradas; 4.10 lógica y cargas                        | XSS almacenado/DOM, inyección, JSON y fotos malformados, duplicación, cuotas y transiciones; adjuntar pruebas negativas.                                                                            |
| V3 frontend, V12 comunicación, V13 configuración            | 4.2 configuración; 4.9 criptografía; 4.11 cliente         | HTTPS/cabeceras del despliegue, rutas estáticas, CORS y cachés reales; secretos e imagen de contenedor.                                                                                             |
| V6 autenticación, V7 sesiones, V8 autorización              | 4.3–4.6 identidad, autenticación, autorización y sesiones | Roles, MFA, sesiones, revocación, CSRF y aislamiento tienen regresiones. Falta evaluación independiente, inactividad, concurrencia y recuperación institucional; completar requisito por requisito. |
| V14 protección de datos, V15 arquitectura, V16 logs/errores | 4.8 errores; 4.10 lógica; 4.11 cliente                    | Borrado/retención, respaldos, fuga de evidencia, abuso, trazabilidad y recuperación.                                                                                                                |

Secuencia: modelo de amenazas → matriz de aplicabilidad → revisión de código/configuración y dependencias → pruebas dinámicas sobre un entorno autorizado con datos sintéticos → correcciones → repetición → informe con riesgo residual. Registrar commit, fecha, herramientas/versiones y destino probado. Android necesita además su propia evaluación móvil y de dispositivo.

El [workflow de seguridad](../.github/workflows/security.yml) incorpora auditoría de dependencias del lockfile, Gitleaks y reglas locales Semgrep; la cobertura SAST es limitada y no incluye un análisis completo de flujo. El [workflow de calidad](../.github/workflows/checks.yml) construye y ejecuta regresiones. Falta DAST y revisión manual independiente del despliegue. Revisar resultados del commit concreto: una ejecución antigua sin avisos no prueba el estado de hoy.

## 5. Operación mínima y recuperación

**Despliegue:** servir con TLS en el ingreso, restringir la API interna, configurar `CORS_ORIGINS`, montar `DATABASE_PATH` en almacenamiento persistente y verificar que el usuario del proceso pueda escribir. No alojar SQLite en almacenamiento efímero para un piloto que prometa conservar evidencia. La topología actual recomendada es una instancia con disco local persistente; varias réplicas requieren revisar persistencia, cuotas y migraciones.

**Salud:** `GET /api/health` confirma que el proceso responde; no prueba capacidad de escritura, espacio libre ni disponibilidad de proveedores. Puede devolver 429 por cuota. Diseñar disponibilidad/readiness por separado y probar el recorrido crítico con datos sintéticos sin publicar observaciones reales.

**Moderación y cuentas:** habilitar el panel en el mismo origen que la API, aprovisionar cuentas mediante CLI y completar TOTP. `analyst` sólo consulta agregados; `moderator|admin` acceden a expedientes y decisiones. Las cuentas no se administran por HTTP. No compartir identidades, registrar evidencia privada en tickets públicos ni confundir el nombre declarado del CLI con la cuenta autenticada web. Procedimientos: [operación administrativa](operacion-admin.md), [API privada](api-administracion.md) y [reportes](quejas-comunitarias.md).

**Respaldo:** el script [backup-reports.mjs](../scripts/backup-reports.mjs) usa la [Online Backup API](https://www.sqlite.org/backup.html) de `node:sqlite`, incluye páginas confirmadas del WAL, verifica integridad y relaciones/esquema y publica una copia 0600 sin sobrescribir. El destino debe ser un directorio privado 0700. Ejemplo sobre rutas elegidas por operación:

```sh
install -d -m 700 /ruta/privada/respaldos/ensayo-2026-10-29
node scripts/backup-reports.mjs /ruta/persistente/regiomovil.sqlite /ruta/privada/respaldos/ensayo-2026-10-29/reportes.sqlite
node scripts/backup-reports.mjs /ruta/persistente/admin-auth.sqlite /ruta/privada/respaldos/ensayo-2026-10-29/accesos.sqlite
node scripts/backup-reports.mjs --check /ruta/privada/respaldos/ensayo-2026-10-29/reportes.sqlite
```

No copiar sólo el archivo `.sqlite` activo. Las dos copias no comparten una transacción: para una instantánea conjunta, coordinar parada del servicio. Cifrar el destino y custodiar el secreto administrativo por separado. El respaldo contiene evidencia y credenciales/MFA sensibles; no alojarlo en web o Git. Las regresiones sobre bases temporales no constituyen un respaldo de producción.

**Restauración:** ensayar en un directorio separado con código compatible; verificar integridad, migración, reportes privados/públicos, fotos, acceso y revocación de sesiones restauradas. Para recuperación real, detener el proceso, preservar bases anteriores y diarios, restaurar a rutas limpias y reiniciar con la configuración correcta. No superponer sobre bases abiertas ni mezclar WAL de instantáneas. El [procedimiento](operacion-admin.md) define los pasos; periodicidad, cifrado, caducidad, RPO/RTO y ejercicio con responsables siguen pendientes de aprobación operativa.

**Retención:** 90 días, 5000 registros y 50000000 bytes de fotos en la base activa. Hay purga al acceder, al iniciar `server/index.mjs` y cada seis horas de ejecución. Un proceso detenido no purga. La base de accesos limita eventos a 90 días y 100000 registros mediante su mantenimiento. Los respaldos y exportaciones necesitan caducidad independiente; no se eliminan con la base activa.

**Incidentes:** usar [SECURITY.md](../SECURITY.md) para divulgación. En operación, restringir el componente afectado, retirar contenido expuesto cuando proceda, preservar evidencia de acceso en un entorno privado y registrar alcance/medidas. Cambiar secretos comprometidos y comprobar corrección antes de reabrir. Faltan responsables nominales, canal operativo y ejercicio de respuesta; no existe un servicio de atención garantizado.

## 6. Observabilidad implementada y despliegue pendiente

El código [observability.mjs](../server/observability.mjs) ofrece un listener separado con `GET|HEAD /metrics`, bearer obligatorio y `no-store`. Sólo se activa con `METRICS_TOKEN` o `METRICS_TOKEN_FILE`, nunca ambos; por defecto escucha en `127.0.0.1:9091`. No exportar el token a `VITE_*`, URL o navegador. El [Compose](../ops/compose.monitoring.yml) conecta aplicación, Prometheus y Grafana con puertos de consola limitados a loopback y métricas en una red interna. Existe dashboard y reglas iniciales probadas localmente; no se ha instalado este stack en el servidor remoto.

| Implementado                                                                                              | Límite / trabajo siguiente                                                                                          |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Solicitudes, abortos y duración por plantilla finita, método y clase de estado                            | No incluye búsqueda, URL completa, IP, UUID, GPS, fotos o texto. No mide por sí solo una ruta del navegador.        |
| RSS, heap, memoria externa, CPU, uptime e intervalo de retraso del bucle de eventos                       | Faltan disco/WAL, supervisión del host, carga de referencia y objetivos de servicio.                                |
| Conteos y cupos agregados de reportes/fotos                                                               | No expone expedientes; falta instrumentar éxito/antigüedad del respaldo, restauración y proveedores específicos.    |
| Prometheus/Grafana con configuración, secretos externos, retención 7 días/512 MB y panel de salud técnica | Grafana sin registro público/acceso anónimo. Hay que revisar identidad, TLS, permisos y retención del destino real. |
| Reglas de alerta por caída, errores, memoria y capacidad                                                  | Umbrales iniciales; sin Alertmanager ni entrega a un canal de guardia. Calibrar y asignar responsables.             |

Separar salud técnica, gestión privada de observaciones y agregados comunitarios públicos. Las consolas del recolector no deben publicarse sin segmentación y autenticación diseñadas. El [modelo de seguridad de Prometheus](https://prometheus.io/docs/operating/security/) considera la información métrica accesible a quien alcance su interfaz. Las etiquetas finitas acotan cardinalidad; ver [instrumentación](https://prometheus.io/docs/practices/instrumentation/).

Habilitación, secretos, redes, parada sin eliminar volúmenes y pruebas: [operacion-admin.md](operacion-admin.md). Antes de una operación sostenida, medir latencia/disponibilidad/capacidad, fijar coste y retención, configurar guardia y ensayar caída/recuperación. Los umbrales de ejemplo no constituyen un SLA ni una garantía operativa.

## 7. Riesgos que bloquean ampliar el piloto

| Riesgo pendiente                                                                         | Responsable por rol       | Evidencia de cierre                                                                              |
| ---------------------------------------------------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------ |
| Copias y purga implementadas sin operación/recuperación institucional ensayadas          | Operación + privacidad    | Restauración ensayada, RPO/RTO aprobados, limpieza y copias con retención probadas.              |
| Evaluación independiente del acceso y recuperación MFA; bitácora modificable por el host | Backend + seguridad       | Pruebas externas, identidad para recuperación comprobada y auditoría con acceso separado.        |
| Cuotas locales y cálculo síncrono expuestos a saturación                                 | Backend + operación       | Pruebas de carga/abuso con topología real, ingreso limitado y memoria estable.                   |
| Contenido identificable y moderación sin equipo/tiempo comprometido                      | Comunidad + privacidad    | Protocolo de revisión/retirada, responsables y pruebas con imágenes sintéticas.                  |
| Revisión OWASP/despliegue, dependencias y cadena de suministro pendientes                | Seguridad + mantenimiento | Matriz ASVS/WSTG, hallazgos priorizados y repetición documentada; controles continuos revisados. |

Continuar mediante la [hoja de ruta](hoja-de-ruta.md). Estas prioridades son recomendaciones técnicas y aún requieren asignación de personas y capacidad.
